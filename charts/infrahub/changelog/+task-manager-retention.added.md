Added the task manager retention settings to `prefect-server.global.prefect.env`: `INFRAHUB_TASK_MANAGER_RETENTION_TASK_HISTORY` (default `30d`) for finished task runs with their logs and artifacts, `INFRAHUB_TASK_MANAGER_RETENTION_ACTIVITY_LOG` (default `7d`) for the events of the activity log, and `INFRAHUB_TASK_MANAGER_RETENTION_PREFECT_OWN_EVENTS` (default `2d`) for Prefect's own events. The list reaches the task manager container and, when Prefect's background services run in their own pod, the background services container, even when an Infrahub Enterprise config preset replaces `server.env` or `backgroundServices.env`. Each value is a number of days such as `30d` or an ISO 8601 duration such as `P30D`, from 1 to 365 days; the task manager does not start with any other value. Infrahub reads these settings from 1.13 on. To change one value, set the whole list, because Helm replaces lists.

Separate background services start through `infrahub tasks background-services`, including deployments without a sizing preset, so they apply these retention settings. Enterprise availability and edition-specific restrictions remain undecided; the current implementation has no edition gate.
