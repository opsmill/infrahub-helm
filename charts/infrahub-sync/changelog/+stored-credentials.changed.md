The worker no longer receives source or destination credentials as `INFRAHUB_SYNC_CREDENTIAL_*` variables: it reads the values of the credentials stored in the Sync API, which an administrator sets with `infrahub-sync credentials set`. Set the key that encrypts them in `credentials.encryptionKey` (required, 32 bytes, base64-encoded, Sync API only) and the token of the `worker` account in `credentials.workerToken` (required, Sync API and worker). The chart gives them as `INFRAHUB_SYNC_ENCRYPTION_KEY` and `INFRAHUB_SYNC_WORKER_TOKEN`, and gives the worker `INFRAHUB_SYNC_API_URL`, which `worker.apiUrl` overrides and which defaults to the Sync API Service of the release over plain HTTP. `credentials.infrahubApiToken`, `worker.credentials` and `worker.credentialsExistingSecrets` are removed, and the chart no longer creates the `<release>-worker-credentials` Secret. Store those values in the Sync API instead. This requires an Infrahub Sync release that has stored credentials.
