Set the Neo4j resource limits equal to the requests in the `small`, `medium`, `medium-data`, `large` and `large-data` config presets. Without a CPU limit, the JVM reports every logical processor on the node as available, and Neo4j sizes its Cypher parallel runtime from that count: `server.cypher.parallel.worker_limit` defaults to `0`, which starts one worker per available processor. On a large node Neo4j started far more parallel runtime workers than the preset's CPU request covered, oversubscribing the CPU the preset was sized for. With the CPU limit in place, the JVM sees the preset's CPU count and the worker pool is sized to match. The memory limit also puts the Neo4j pod in the Guaranteed QoS class; the JVM heap and page cache stay pinned by `server.memory.*`, leaving at least 7 GB of each limit for off-heap allocations and the operating system. Override `infrahub.neo4j.neo4j.resources.limits` to change the caps, or set `infrahub.neo4j.config.server.cypher.parallel.worker_limit` to size the worker pool explicitly.
